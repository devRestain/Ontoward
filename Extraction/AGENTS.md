- Own the independent python -m ontoward_extraction builder, prompts, pinned image, provider adapters, and checkpoint tests. Use root PROJECT_STATE.md for progress and data/ for durable results.
- Apply D49 and read ../data/ontology/AGENTS.md before changing emitted knowledge. Keep one provider per immutable build fingerprint and no automatic provider/model/account fallback.
- Start from supplied RF2 Snapshot/releases, eight BODHI CSVs, DDXPlus evidence/condition metadata, and allowlisted Astra candidate/binding/CPX fields. Exclude patients, old generated bundles/work DBs, and Astra snapshots/policies.
- Index raw inputs in SQLite; select latest RF2 rows before active use and check exact module/release dependencies. Preserve input hashes, phase/chunk cursors, prompts/contracts, requests, responses, accepted rows, usage, retries, and unknown outcomes transactionally.
- Use draft gpt-6-luna medium and final gpt-6.1-sol medium. Use NOVA session-free Client.chat, ChatGPT-authenticated read-only codex exec, or tool-free Responses structured output as explicitly selected.
- Keep NOVA/API output limits at 8000/32000, timeout at 600 seconds, and Codex CLI at 0.162.1. Manage CLI by finite work batches and timeout; do not claim a token cap it cannot enforce.
- Disable Codex shell, web, agents, config inheritance, and API-key authentication for the subscription route. Keep authentication in the new dedicated volume and never inspect or copy the old auth volume.
- Keep only provider-required credentials in each adapter. Never log credentials or run login/model calls as an offline check.
- Include the exact response schema in NOVA system messages; treat this as prompt guidance with strict local acceptance, not native structured-output enforcement. Keep API and Codex native schema routes unchanged.
- Freeze finite phase worksets; accept valid sibling rows and repair missing/invalid rows within bounded attempts. Use final model knowledge for general relationships; generate no patient observations.
- Normalize clinical concepts and roles before generating action text. Set question, exam_text, and attribute_role.clarification to null in normalization requests and project premature action fields out before normalization validation; preserve clinical fields and raw responses. Apply the same projection when reading historical done normalization results without rewriting them.
- Generate Korean action text only in questions or later completion phases. Require Hangul, NFC, and 1-30 rendered codepoints; explain field, length, normalization, language, and question-invariant failures. Preserve presence-only affirmative binding and numeric-unit validation.
- Hold a single worker lock. Honor explicit pause, SIGINT, and SIGTERM before new jobs/requests; save the in-flight response and accepted rows before paused exit.
- Recover durable responses locally. Recover NOVA with its same ID/payload; require --retry-unknown for uncertain API/CLI transmissions and retain the superseded attempt. Require --resume for existing checkpoints.
- Preserve a confirmed NOVA PROVIDER_RESPONSE_INVALID as a failed request and use a fresh ID for the next bounded attempt with unchanged payload settings. Keep unknown transport outcomes on the original ID. Limit transmission attempts to five and prevent replacement requests from consuming additional output-validation attempts. Log HTTP status and old/new request IDs.
- Compile only in output staging, verify through the production loader, and install build-specific files before atomically replacing the root manifest. Never overwrite an immutable build with different bytes.
- Keep status/pause independent of clients and keys, verify offline/read-only, restart disabled, and Compose stop grace at 660 seconds.
- Run synthetic end-to-end/pause/provider tests in project containers. Keep actual login, model access, generation quality, real DB creation, and real installation unrun in D49 acceptance.

- Parse RF2 as literal TSV with quotes preserved and BODHI with normal CSV quoting. Reject malformed row widths with file/line context. Never reuse the failed pre-fix index; preserve its bytes and start a new fingerprint.
- Keep human and watched status read-only and keyless. Report committed cursors and phase-specific work without inventing an overall percentage or ETA. Use extraction.sh for durable console logs and preserve the Docker exit code.
- Report request starts, accepted/invalid row counts, and bounded validation reasons. Mark only exhausted jobs failed and keep untried jobs pending.
- Run recover-normalize without network or credentials. Accept only closed fully indexed NOVA normalization failures with no accepted results or unsettled requests and matching inputs, models, parser, schema, and runtime. Copy into a new fingerprint atomically; retain the original DB, responses, usage, and prior attempt counters. Never use this path for the invalid pre-fix RF2 index.
- Use recover-normalize-text for settled paused normalization action-text failures under the same input and clinical contracts. Preserve done result bytes and counters; replay latest saved eligible pending responses without model calls or duplicate usage, preserve recovery history, and publish only a completed staged copy.
- Use recover-normalize-provider only for failed normalization with confirmed PROVIDER_RESPONSE_INVALID records and identical inputs, prompts, models, and clinical contracts. Preserve every done row and attempt counter; retire only confirmed cached-error records, keep their payload/error, requeue unfinished jobs, and reject unknown outcomes.
