01

먼저, 전체 지도

진료 전에는 일반 지식과 한국어 행동 문구를 준비합니다. 진료 중에는 수용된 그래프를 읽으며 한 환자의 사실만 갱신하고, 마지막에 SOAP와 주진단을 제출합니다.

사전 준비현재 진료 경로기본 생략·후속 준비

컴포넌트를 읽는 기준

  • Python이 선택하고 계산합니다.

    질문 순서, 그래프 이동, 점수, 진단, SOAP는 코드가 결정합니다.

  • 모델은 환자의 말을 사실 후보로 해석합니다.

    지정 Luna Gateway의 결과는 Python 검증을 거쳐 기록에 들어갑니다. Doctor는 준비 문구를 전달합니다.

현재 채택된 실행 설정

  • 지식·한국어 문구: admitted

    manifest가 실행 자산을 고정합니다. 원천 의미·단위·획득 경로가 부족한 항목은 기술적으로 제외됩니다.

  • Education: 기본 pass

    교육 행동·교육 보호 턴을 사용하지 않으며 P.education은 빈 문자열입니다.

02

한 환자의 진료는 어떻게 흐를까

공식 NOVA 세션 하나 안에서 Consultation이 다섯 내부 단계를 조정합니다. 각 단계의 대화 수는 고정되어 있지 않으며, 같은 행동 루프와 공통 예산을 사용합니다.

  1. 1
    Initiation진료 시작

    초기 원문·활력징후를 보존하고, 준비된 인사와 주호소 유도로 시작합니다.

    첫 실질적 진술은 Gateway로 해석합니다. D29는 보고된 각 현재 주호소를 제공된 Symptom 하나에 연결하도록 요구합니다.

  2. 2
    ChiefComplaint현재 불편의 구체화

    핵심 HPI → Open Inquiry 한 번 → 적응형 ROS·나머지 속성.

    위치 · 좌우 · 양상 · 시작 후 경과 · 한 번의 지속시간 · 강도를 적용 가능한 미해결 슬롯부터 확인합니다. 여러 주호소는 슬롯별로 번갈아 묻습니다. ROS는 최초 주호소 계통 안에서 총 6회 이내입니다.

  3. 3
    ContextFactor병력과 적용 조건

    후보와 연결된 병력·Context, Association의 미해결 적용 조건을 확인합니다.

    더 유용한 소견 질문·진찰이 앞서면 감별 단계로 넘어갑니다. 남은 Context도 이후에 함께 비교할 수 있습니다.

  4. 4
    DifferentialDiagnosis감별을 위한 정보수집

    가상 답에서 순위를 바꿀 수 있는 질문·진찰을 고르고, 실제 응답 뒤에 추론과 미전송 질문을 갱신합니다.

    속성 문진은 같은 관찰·발현의 Target 존재가 확인되어야 합니다. EXAM 거절·오류는 획득 소견으로 기록하지 않습니다.

  5. 5
    Education기본 설정에서 생략

    진단을 선택하고 교육 행동 없이 최종화로 진행합니다.

    현재 ONTOWARD_EDUCATION_ENABLED=false. 명시적으로 활성화한 경로의 설명·이해 확인·정정은 현재 기본 실행에 포함되지 않습니다.

D35 문진 목표 / 상한: Initiation 1/1 · ChiefComplaint 7/16 · ContextFactor 2/7 · DifferentialDiagnosis 3/12 · Education 0/0. 유용한 질문이 없으면 최소 목표 전에도 종료하고 남은 횟수를 다른 세션에 넘기지 않습니다. 문진은 최대 36회이며 공감 SAY는 별도로 집계하면서 공통 50턴·모델 예산을 사용합니다. 14턴은 고정 공감 할당량이 아닙니다.

매 질문에서 반복하는 공통 루프

  1. 01 / select_question

    미전송 질문 선택

    InterviewPlanner가 현재 단계와 사실에서 준비된 질문을 고릅니다.

  2. 02 / validate_action

    문구와 행동 검증

    Doctor가 NFC 1–30자와 준비 계약을 확인합니다. 문장을 생성하거나 자르지 않습니다.

  3. 03 / execute_action

    SAY 또는 EXAM 실행

    전송 직전 경량 자원 검사를 통과하면 SDK로 전달하고 실제 응답·전달 이력·사용량을 보존합니다.

  4. 04 / process_input

    응답을 사실로 수용

    단축 계약 또는 Gateway로 해석한 뒤 인용·타입·참조·주체·시점을 검증합니다.

  5. 05 / refresh_after_input

    추론 갱신과 재계획

    변경 근거로 후보·미전송 질문을 갱신하고 check_budget으로 돌아갑니다.

새 답 → 사실 갱신 → 다음 질문 또는 세션 전환 · 예산 부족 시 최종화

모델 결과가 곧 환자 사실은 아닙니다. 현재 응답의 정확한 인용과 제공된 ID를 검증합니다. 독립 유효 사실은 보존하고 무효 의존 사실은 격리합니다. JSON·문맥·개념 연결·사실 복구는 응답당 추가 호출 한 번을 공유합니다.

예산을 다 쓰기 전에 제출 준비

  • SAY·EXAM 공통 50턴

    모델은 증례 전체 최대 200회, 입력 500,000·출력 100,000토큰입니다. 그래프 노드 수는 행동 턴 수와 다릅니다.

  • 새 행동 전 응답·최종화 여유 확보

    Gateway 1회·출력 2,048토큰, 응답 처리 120초와 최종화 120초 여유를 확인합니다. 이미 받은 마지막 응답도 먼저 처리합니다.

문제가 생기면 제한적으로 복구

  • 의미 명료화는 증례 전체 2회

    원문과 미해결 상태를 남깁니다. 후보를 끝내 확정하지 못하면 근거가 있는 주호소의 증상 진단을 검토합니다.

  • 일시 전송 오류는 같은 요청을 재확인

    같은 ID·payload로 2초 후 한 번 재전송하며 미해결이면 unknown으로 종료합니다. 환자·진찰 형식 오류는 새 ID 자동 재시도 없이 미확인으로 남깁니다. SOAP 재구성은 합쳐 1회입니다.

마지막은 SOAP 구성 → 검증 → DIAGNOSE → 영수증 확인

S6개 필드

cc · hpi · pmh · fh · sh · ros
환자가 보고한 증상·병력·맥락

O2개 필드

exam · tests
초기 제공 정보·실제 진찰
예선 O.tests는 빈 문자열

A2개 필드

evidence · differential
실제 획득 근거·적격 감별 최대 5개

P5개 필드

tests · treatment · disposition
follow_up · education
수용 자산 범위만 사용

별도 인수 diagnosis로 주진단 하나를 보냅니다. 현재 manifest에는 질환별 plans가 없으며, P.tests도 실제 연결이 있어야 채웁니다. 교육 필드는 기본 빈 문자열입니다.

정상 종료 조건: status == "completed" → termination=submitted. 최종 응답이 실패·불명·만료·폐쇄이면 비정상 결과로 남깁니다.

03

관찰이 질환 적합도가 되는 과정

ClinicalReasoner가 현재 관찰을 공유 Pattern과 비교한 뒤 질환별 연결 조건과 원천 가중치를 적용합니다. 점수는 후보 정렬을 위한 적합도이며, 보정된 진단 확률은 아닙니다.

  1. 01 / 관찰별 묶기

    환자·현재·출처를 확인

    관찰 ID와 발현 ID로 분리합니다. 다른 발현의 위치와 기간을 섞어 Pattern을 완성하지 않습니다.

  2. 02 / Target으로 넓게 검색

    연결된 질환 후보 회수

    present·uncertain Target의 연결을 사용합니다. BodySystem으로 질환 검색 범위를 자르지 않습니다.

  3. 03 / 공유 Pattern 평가

    Feature 조건을 함께 비교

    존재·개념·개념 집합·수치·구간을 평가합니다. 모든 조건이 맞아야 matched입니다.

  4. 04 / Association 적용

    질환별 적용 조건과 원천 점수

    Pattern과 applicability가 모두 matched일 때만 지지를 활성화합니다. 미완성 조건은 질문 재료로 남습니다.

  5. 05 / 정교화·중복 정리

    더 구체적인 표현으로 대체

    완전 매칭한 정교화가 조상을 대체합니다. 이후 같은 Disease–Target의 최대 기여 하나만 남깁니다.

  6. 06 / 적합도와 자격

    정렬한 뒤 진단 자격 확인

    지지·Context·제한 반증을 계산하고, 양성 지지와 전체 확정 주호소 설명 여부로 진단을 선택합니다.

matched · 모두 일치

전체 Feature가 맞고 적용 조건도 통과해야 원천 지지에 반영합니다.

contradicted · 명시적 반증

한 조건이라도 명시적으로 반대면 다른 조건의 unknown보다 우선합니다.

incomplete · 아직 미완성

반증은 없지만 unknown이 남은 경우입니다. 추가 확인할 질문을 만듭니다.

구체적인 정보가 점수를 낮출 수도 있습니다

같은 질환·Target에 아래 원천 가중치가 있다고 가정한 설명용 예입니다.

04

다음에는 무엇을 물을까

핵심 HPI와 Open Inquiry 이후에는 InterviewPlanner가 질문별 가치 벡터를 비교합니다. 같은 답에 대한 점수 변화 시나리오를 사용하는 결정론적 휴리스틱이며, 응답 확률을 추정하는 기대 정보이득은 아닙니다.

왼쪽 값이 먼저 다르면, 그 자리에서 우선순위가 정해집니다

1순위 변경

가정한 답에서 다른 후보가 현재 선두의 fit을 넘을 수 있는가

2변화량 차이

시나리오별 후보의 최대 변화와 최소 변화 사이 간격

3조건 해소 가치

남은 조건 비용당 원천 지지 변화의 최대값

4주호소 Target

현재 확정 주호소의 Target에 해당하는가

5전형성

원천 typicality를 공개 라벨 점수로 바꾼 값

[1, 0.2, 0.1, 0, 0]먼저 선택[0, 4, 4, 1, 4]

가중합이 아니므로 뒤의 큰 값으로 첫 번째 값의 차이를 뒤집지 않습니다. 벡터가 같으면 비Context 질문을 먼저 두고, 마지막에는 의미 키로 순서를 정합니다.

한 질문의 계산 예

현재 A의 fit=4, B의 fit=3이라고 가정합니다. 어떤 답이 A에는 0, B에는 +2를 만들고 미해결 조건이 하나라면 B의 추정 fit은 5가 됩니다.

이 시나리오에서 순위 변경=1, 변화량 차이=2, 조건 해소 가치=2가 될 수 있습니다. 같은 변화를 여는 조건이 두 개면 조건 해소 가치는 1로 줄어들 수 있습니다.

선택을 제한하는 실제 규칙

  • Context 가점은 최대 +1

    상한을 이미 채운 Context는 가점 가치가 소진됩니다. 단, 필수 적용 조건을 해결하는 역할은 남을 수 있습니다.

  • 미전송 계획만 새로 만듭니다

    대기 행동·완료 사실·실제 전달 이력은 유지합니다. 명료화는 증례 전체 2회 한도를 따릅니다.

D35 종료 규칙: 선택적 질문은 앞의 세 가치 중 양수가 있어야 합니다. 최소 목표 이후에는 순위 변경이나 변화량 차이가 양수이거나, 적격 Disease가 없으면서 조건 해소 가치가 양수여야 계속합니다. 핵심 HPI·Open Inquiry·명료화·교육·공감은 가치 필터 예외이며 자원 한도는 따릅니다. 이는 확신도나 확률 기반 정보이득을 계산한 정책은 아닙니다.

05

진료에 들어가기 전, 지식의 준비

원천 보존, 후보 투영, 한국어 문구 준비, 실행 수용은 서로 다른 단계입니다. 진료 중에는 원본 RF2나 지침 문서를 다시 읽지 않고 submission/ 내부에 고정된 자산을 사용합니다.

  1. 원천을 보존

    공급된 SNOMED CT International·Korean Snapshot과 BODHI-S를 assets에 그대로 두고, SQLite에 원천 파일·행·판본·관계 그룹·해시를 보존합니다.

  2. v5.0 후보를 투영

    Dev/ontology가 어휘·Feature·공유 Pattern·질환별 Association을 구성합니다. ROS·typed Context·필수 조건·선택 진찰 경로는 원천 근거를 보존해 연결합니다. 해결되지 않은 역할·단위·획득 방식은 공백으로 남깁니다.

  3. 환자 행동 문구를 준비

    D22는 문진·속성·Context·진찰 요청 1,309개에 대해 NOVA 생성과 별도 의미 대조를 완료했습니다. Korean RF2 명칭과 모델 생성 문구의 출처를 구분하며, 별도 NFC 1–30자 검증을 적용합니다.

  4. 정확한 빌드로 실행 수용

    D20 그래프와 D22 문구의 고정 해시를 D23 수용 영수증에 연결합니다. 현재 manifest는 admitted입니다. 완전한 후보에 추가 승인 대기는 없으며, 불완전한 표현은 기술적 제외로 유지합니다.

  5. 독립 실행 자산을 구성

    prepare가 파일 경계·해시·문구를 엄격하게 확인합니다. 패키지는 runtime Python·고정 requirements·공개 설정·필요 지식만 포함하며, Test·Dev·data·원본·문서·로컬 키는 제외합니다.

별도 준비 가지 · D30 가이드라인 매핑

수용된 Disease → 제공 가이드라인 문서·원문 구간 → 향후 SOAP P 근거 추출.

문서 매핑은 완료된 준비 결과이며 환자별 계획 생성·런타임 plans 수용은 후속입니다. background_only 연결은 P 근거 확보와 별도로 집계합니다. 현재 Education pass를 유지합니다.

지식은 공유하고, 환자는 분리합니다. PreparedResources에는 일반 지식과 설정만 둡니다. 관찰·원문·점수·질문·사용량은 consult마다 새로 만드는 증례 상태에 남기며, 읽기 전용 RDFLib Graph에 환자 사실을 쓰지 않습니다.
