01

먼저, 전체 지도

진료 전에는 일반 지식과 한국어 행동 문구를 준비합니다. 진료 중에는 수용된 그래프를 읽으며 한 환자의 사실만 갱신하고, 마지막에 SOAP와 주진단을 제출합니다.

사전 준비현재 진료 경로조건·기술적 제외

컴포넌트를 읽는 기준

  • Python이 선택하고 계산합니다.

    질문 순서, 그래프 이동, 점수, 진단, SOAP 직렬화는 코드가 결정합니다. 영어 P 내용은 D37에서 모델이 생성하고 검증합니다.

  • 모델은 환자의 말을 사실 후보로 해석합니다.

    지정 Luna Gateway의 결과는 Python 검증을 거쳐 기록에 들어갑니다. Doctor는 준비 임상 문구와 검증된 공감·교육 생성 문구를 전달합니다.

현재 채택된 실행 설정

  • 지식·한국어 문구: admitted

    manifest가 실행 자산을 고정합니다. 원천 의미·단위·획득 경로가 부족한 항목은 기술적으로 제외됩니다.

  • Education: 기본 활성화

    진단을 고정하고 영어 P를 생성한 뒤 한국어로 안내합니다. 앞선 수집에서 5턴을 보호합니다.

03

한 환자의 진료는 어떻게 흐를까

공식 NOVA 세션 하나 안에서 Consultation이 다섯 내부 단계를 조정합니다. 각 단계의 대화 수는 고정되어 있지 않으며, 같은 행동 루프와 공통 예산을 사용합니다.

같은 그래프 안에서 바뀌는 다섯 내부 세션

  1. 1
    Initiation초기 정보와 공통 문진

    초기 정보를 먼저 구조화하고 “안녕하세요. 병원 오시는 길이 불편하진 않으셨나요?”로 시작합니다.

    미확인 onset·course·이전 유사 경험·치료 경험을 순서대로 묻습니다. 환자·보호자와 등록 수치·감사 전용 정보를 구별하며 이미 확인한 주호소를 반복 유도하지 않습니다.

  2. 2
    ChiefComplaint현재 불편의 구체화

    환자가 우선시한 대표 CC 하나 → 연결된 전체 속성 처리 → Open Inquiry 한 번 → 유용한 ROS·필요 상세.

    get_symptom_attributes 전체 목록을 안정된 순서로 처리하고 acquired·recorded_unmapped·unknown·not_applicable·blocked_asset·budget_stopped를 구분합니다. 마지막 가용 슬롯은 Open Inquiry에 남깁니다. ROS는 대표 CC의 원래 계통에서 총 6회 이내이며 추가 증상으로 확장하지 않습니다.

  3. 3
    ContextFactor병력과 적용 조건

    과거력·약물·알레르기·가족력·사회력의 미확인 영역 뒤 관련 Context 최대 두 개를 보호 수집합니다.

    미확인 전제·utility·새 병력 영역·URI 순으로 선택합니다. utility 0이나 가산점 포화만으로 생략하지 않으며 보호 수집을 마친 뒤 선택적 질문·진찰을 비교합니다.

  4. 4
    DifferentialDiagnosis감별을 위한 정보수집

    가상 답에서 순위를 바꿀 수 있는 질문·진찰을 고르고, 실제 응답 뒤에 추론과 미전송 질문을 갱신합니다.

    속성 문진은 같은 관찰·발현의 Target 존재가 확인되어야 합니다. EXAM 거절·오류는 획득 소견으로 기록하지 않습니다.

  5. 5
    Educationworking 진단 후 계획·안내

    working 진단과 미해결 평가를 고정하고 지침 원문·canonical 환자 사실·전달 가능 턴으로 영어 P와 한국어 설명을 준비합니다.

    현재 ONTOWARD_EDUCATION_ENABLED=true. 조건을 포함한 전체 묶음을 NFC 1–30자·용량 검증 뒤 연속 전달합니다. 환자 답변은 원문만 기록하며 해석·공감·임상 상태 변경을 실행하지 않습니다.

D40 조건부 목표 / 상한: Initiation 5/7 · ChiefComplaint 7/14 · ContextFactor 7/9 · DifferentialDiagnosis 3/10 · Education 5/10. 기확인·해당 없음·자산 부족으로 질문을 채워 넣지 않고 상한을 빌리지 않습니다. 선택적 질문·공감 전에 현재 필수 수집·뒤 세션 최소량·교육 5턴을 보호합니다. 공감도 공통 50턴을 소비하므로 모든 상한을 동시에 보장하지 않습니다.

매 질문에서 반복하는 공통 루프

  1. 01 / select_question

    미전송 질문 선택

    InterviewPlanner가 현재 단계와 사실에서 준비된 질문을 고릅니다.

  2. 02 / validate_action

    문구와 행동 검증

    Doctor가 NFC 1–30자와 준비 계약을 확인합니다. 임상 문진·진찰은 준비 문구를, 공감·교육은 검증된 생성 문구를 사용하며 자르지 않습니다.

  3. 03 / execute_action

    SAY 또는 EXAM 실행

    전송 직전 경량 자원 검사를 통과하면 SDK로 전달하고 실제 응답·전달 이력·사용량을 보존합니다.

  4. 04 / process_input

    응답 수신과 역할별 처리

    초기 입력과 모든 수집 답은 문맥 분석·DB 정규화를 거칩니다. 원문은 해석 문맥과 감사에만 사용합니다. Education 답은 원문·수신·전달 완료만 기록합니다.

  5. 05 / refresh_after_input

    수집 근거 갱신과 다음 행동

    수집 중 변경 근거로 재계획합니다. Education은 임상 상태를 유지하고 다음 유효 묶음의 전달 여유를 확인합니다.

새 답 → 사실 갱신 → 다음 질문 또는 세션 전환 · 예산 부족 시 최종화

모델 결과가 곧 환자 사실은 아닙니다. 현재 응답의 정확한 인용과 제공된 ID를 검증합니다. 독립 유효 사실은 보존하고 무효 의존 사실은 격리합니다. JSON·문맥·개념 연결·사실 복구는 응답당 추가 호출 한 번을 공유합니다.

예산을 다 쓰기 전에 제출 준비

  • SAY·EXAM 공통 50턴

    모델은 증례 전체 최대 200회, 입력 500,000·출력 100,000토큰입니다. 그래프 노드 수는 행동 턴 수와 다릅니다.

  • 새 행동 전 응답·최종화 여유 확보

    수집은 문맥 분석·정규화 최소 2회·출력 8,192토큰을 확보하며 단계별 복구는 최대 8,000토큰을 요청합니다. 준비된 교육은 답변 모델을 예약하지 않습니다. 응답 120초·최종화 120초와 마지막 수신 소비를 유지합니다.

문제가 생기면 제한적으로 복구

  • 의미 명료화는 증례 전체 2회

    원문과 미해결 상태를 남깁니다. 후보를 끝내 확정하지 못하면 근거가 있는 주호소의 증상 진단을 검토합니다.

  • 일시 전송 오류는 같은 요청을 재확인

    같은 ID·payload로 2초 후 한 번 재전송하며 미해결이면 unknown으로 종료합니다. 환자·진찰 형식 오류는 새 ID 자동 재시도 없이 미확인으로 남깁니다. SOAP 재구성은 합쳐 1회입니다.

04

대표 CC에 대한 근거가 적합도가 되는 과정

실제 입력과 가상 답변은 같은 ClinicalReasoner.evaluate / evaluate_delta를 사용합니다. 후보 회수, 완전 지지, 진단 자격을 구분하며 점수를 진단 확률로 해석하지 않습니다.

matched

모든 Feature와 필수 적용 조건이 맞아야 지지를 활성화합니다.

contradicted

명시적 반증이 unknown보다 우선합니다. 상세 불일치가 곧 감점은 아닙니다.

incomplete

미확인 조건은 질문 경로로 남기며 실제 지지로 앞당겨 계산하지 않습니다.

대표 CC와 같은 Target의 다른 관찰은 추가 보강에서 제외합니다. 제한 반증은 기본 존재 Pattern·충족된 applicability·활성 CC 발현의 명시적 현재 부재·양성 기록 없음에만 적용하며 typicality high=0.5, very_high=1입니다. unknown·미질문·상세 불일치·다른 발현 부재는 감점하지 않습니다.
