프롬프트도 호출자가 고릅니다

Ear의 initial/reply/exam, 세션의 rank/decision/action, Education의 plan.generate/repair, Mouth의 announcement/표현 복구를 Python에서 선택합니다. 공유 관계 정의는 한 JSON 입력의 relations 표에 한 번만 넣고 지역 참조로 재사용합니다. 모델이 작업 경로를 고르거나 전체 상태를 읽도록 맡기지 않습니다.

진료 모델은 openai/gpt-6-luna입니다. 임상 판단과 영어 P·한국어 공동 생성은 high, Ear와 남은 Mouth 표현·복구는 medium입니다. 공감은 검증된 템플릿을 사용합니다. 추출 모델은 별도 설정입니다.

언제 모델을 다시 부르나요?

환자 사실은 RDF나 추출 SQLite에 저장하지 않습니다. 증례 메모리의 CaseState.facts가 유일한 정본입니다.

예시: “이틀째 기침이 있고 열은 잘 모르겠어요”

  1. Ear가 분리합니다. 기침 존재, 기간 2일, 발열 미확인을 독립적으로 해석합니다. 등록 연결이 가능한 부분만 graph_binding을 붙이고 원래 수치·단위를 보존합니다.
  2. Python이 수용합니다. ID·SAY source·turn·환자·현재 episode를 부여합니다. 일부 행만 실패하면 해당 행만 복구하고 정상 형제와 demographic을 유지합니다.
  3. 그래프 자격을 계산합니다. 기침의 같은 scope 존재가 확인되어야 기침 기간을 근거와 속성 질문에 사용할 수 있습니다. 발열 unknown을 absent로 바꾸지 않습니다.
  4. 세션이 판단합니다. 등록 관계의 supports/against/unresolved를 구성하고, 해당 세션의 호출 시점에서만 Brain을 사용합니다.
  5. Writer가 기록합니다. 환자 SAY의 기침·기간은 주관적 정보로 기록합니다. 환자가 말한 “열”을 객관적 EXAM이나 실제 체온으로 바꾸지 않습니다.

이 예시는 자료 변환 설명용입니다. 현재 설치된 질환·관계나 실제 환자/임상 검증 결과를 나타내지 않습니다.

후보 회수와 효과 활성화는 다른 단계입니다. 넓게 찾되, 전체 조건이 맞는 관계만 실제 근거가 됩니다.

불확실성·부정·실행 질문을 다루는 규칙
판정 상황 근거 처리 다음 질문
전체 Feature와 applicability 부합 관계의 support/strong_support/against/strong_against 활성 다른 미확인이나 감별 질문을 검토합니다.
일부 Feature만 부합 부분/미확인으로 유지; 활성 effect 아님 같은 target/scope의 실행 가능한 미확인만 질문 후보로 만듭니다.
명시적 모순 등록 effect를 반대 effect로 뒤집지 않음 이미 불가능한 관계를 완성하려고 남은 조건을 묻지 않습니다.
서로 다른 가족/episode의 조각 한 Pattern으로 결합하지 않음 각 scope에서 존재·속성을 확인합니다.
속성만 있는 Pattern 속성 수치만으로 Target 존재를 만들지 않음 같은 Target·scope의 존재 질문이 먼저입니다.
유효 순위 + 잘못된 행동 정상 Assessment를 보존 action-only 제한 복구로 실행 가능한 질문을 선택합니다.

질문은 어떻게 실행 가능해지나요?

필수 질문은 세션이, 선택 질문은 등록 관계의 미확인 feature와 진찰 경로에서 준비합니다. 같은 scope key의 질문을 먼저 합치고, 이미 답함·unknown·자산 차단·중복·잘못된 시점·존재 미확인·예산 부족을 검사합니다. attribute_roles가 순서·SOAP category·clarification을 정합니다. 물리 EXAM은 환자의 current 시점에서 등록된 단일 동작으로 실행합니다.

현재 모든 후보는 유효한 그래프 경로가 있는 동안 보존하며 Top-K나 수치 임상 점수를 사용하지 않습니다. refinesPattern은 같은 effect·scope·applicability·관찰 안에서만 세부 패턴을 적용합니다. 반복된 같은 관찰을 여러 독립 지지처럼 더하지 않습니다.

트랜잭션과 잠금

journal_mode=WAL과 synchronous=FULL을 사용하고, worker 하나만 .worker.lock의 비차단 flock을 잡습니다. prepare_request는 요청 기록과 job 시도 수를 함께 쓰고, accept는 valid 결과·invalid retry·usage·요청 accepted를 같은 transaction에 반영합니다. done과 neutral을 다시 모델에 보내지 않습니다.

색인에는 rf2_concept와 rf2_source JSON expression index를 만들고 phase workset은 meta의 동결 표식으로 고정합니다. 백업/복구는 jobs.sqlite3만 무조건 복사하는 작업으로 설명하면 안 됩니다. WAL과 worker 상태를 포함한 정해진 정지·복구 절차를 따라야 합니다.

SAY·EXAM은 서버가 확인한 소비를 사용합니다. 내부 판단·세션 조회·SOAP·DIAGNOSE는 환자 행동 턴이 아닙니다. 공통 상한은 50행동, 모델 200회, 입력 500,000·출력 100,000토큰이며 Education 7턴과 최종화 자원을 보호합니다. 성공 응답의 예산을 재사용하고 최초·불명 소비·서버 한도 오류·제출 직전에 동기화합니다.

세션이 남은 필수 질문 수를 정수로 BudgetPolicy에 제공하며 Budget이 지식을 다시 조회하지 않습니다. 발화는 매번 NFC 한국어 1–30 codepoint를 검증하고 자르지 않습니다. Education 비활성 설정은 해당 행동·예약·P.education을 사용하지 않습니다.

독립 ZIP에는 무엇이 들어가나요?

runtime Python, 고정 requirements, 공개 .env, 참조 프롬프트·문구, manifest와 다섯 자산만 허용합니다. 원자료·Extraction·Test·Dev·SQLite·인증·문서·상태·캐시는 제외합니다. 합성 ZIP은 Tmp/에서만 검증하며 실제 설치 전 정식 패키징은 중단해야 합니다.
