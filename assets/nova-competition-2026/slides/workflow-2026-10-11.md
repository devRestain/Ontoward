# 한눈에 보기
참가자가 만드는 것은 run.py 하나이고, 그 안의 두 함수가 핵심
prepare() — 진료 전에 한 번. 모델·검색 자료 같은 것을 불러옴. 이때는 환자 정보에 접근할 수 없음
consult(client, state) — 진료. client로 환자에게 묻고(SAY), 진찰하고(EXAM), Doctor 모델을 부르고(chat), 마지막에 기록을 제출(DIAGNOSE)
run_agent(prepare, consult)는 이 둘을 정해진 순서로 이어 주는 SDK 함수. 순서는 늘 같음
준비 prepare()
최대 10분 · 증례 접근 불가
준비 완료 신호
client.ready()
진료 consult()
최대 30분 · 50턴
기록 제출
client.diagnose()
채점
채점 모델이 기록 평가

컨테이너  서버는 증례마다 새 컨테이너를 띄워 python run.py를 실행합니다. 증례 5개를 평가하면 이 과정이 5번 반복되고, 증례끼리 메모리나 파일을 공유하지 않습니다.

# consult 안의 행동: client가 하는 일
| 함수 | 하는 일 | 서버 안에서 | 턴 | 주요 오류 |
| --- | --- | --- | --- | --- |
| client.session() | 시작 정보(첫 줄·활력징후), 남은 턴, 가능한 행동, 마감 시각 | 대본·진찰표·체크리스트는 주지 않음. 서버 실행에서는 지난 행동 기록(events)도 오지 않음 | 0 | 409 MODEL\_NOT\_READY (ready 전) |
| client.chat() | Doctor 모델(gpt-oss-20b)을 OpenAI 형식으로 호출 | 한도 확인(세션당 200회 · 입력 50만 · 출력 10만 토큰) → 엘리스에 스트리밍 요청 → 완성된 답을 한 번에 돌려줌 | 0 | 403 MODEL\_NOT\_ALLOWED 400 INVALID\_COMPLETION\_FIELDS 503 PROVIDER\_RESPONSE\_INVALID (빈 답) |
| client.say() | 환자에게 질문·설명 (1~30자, 한 번에 하나) | 가상 환자 모델(gpt-6.1-sol low)에 규칙 + 비공개 지시문 + 대본 + 대화를 보냄 → {content, effective\_content}. 형식 오류면 503을 돌려줌(참가자 코드가 다시 보냄) | 1 | 400 CONTENT\_TOO\_LONG · EMPTY\_CONTENT (1턴) 503 PATIENT\_RESPONSE\_INVALID (0턴) |
| client.exam() | 신체진찰 동작 하나를 문장으로 요청 | 진찰 판정 모델(gpt-6.1-sol low)이 진찰표 행 하나에 연결 → 서버가 그 행의 정해진 결과를 돌려줌 (모델이 소견을 지어낼 수 없음) | 1 | 422 EXAM\_NOT\_SPECIFIC · EXAM\_NOT\_RECOGNIZED (1턴) 503 EXAMINER\_RESPONSE\_INVALID (0턴) |
| client.diagnose() | S·O·A·P 15칸(빈 문자열 가능, 전부 비면 안 됨) + 주진단 한 줄 제출 | 세션 종료, 채점용 기록 텍스트(note) 생성, record\_digest 반환. score\_status는 pending | 0 | 이후 모든 요청은 409 SESSION\_CLOSED |

예선에서는 gpt-oss-20b만 쓸 수 있음(model을 다르게 주면 403 MODEL_NOT_ALLOWED). 서버가 Doctor 설정을 고정 버전으로 잠금
참가자가 정할 수 있는 것은 messages, max_tokens, reasoning_effort(low·medium·high), temperature(0~2)뿐. tools·stream·response_format 등을 넣으면 400 INVALID_COMPLETION_FIELDS
completion_tokens 267에는 화면에 안 보이는 추론 토큰이 포함. 이 답은 42자라 30자를 넘으므로, 기본 에이전트였다면 버리고 다시 물었을 것
답이 비어 있으면(추론만 하고 끝난 경우) 503 PROVIDER_RESPONSE_INVALID. 팀 요금·토큰 한도·효율 점수의 Doctor 비용에 넣지 않고 호출 200회에만 셈. 턴은 어떤 경우에도 쓰지 않음
GPT-OSS-20B의 경우에는 답을 비워 출력하는 경우가 있으니 처리 필요.

# 진찰(EXAM) 요청은 어떻게 판정되나
| 판정 | 서버 동작 | 턴 | 실제 예시 (요청 → 응답) |
| --- | --- | --- | --- |
| 진찰표 행에 연결 | 그 행의 정해진 결과를 돌려줌. 서버 기록에 effective\_content로 그 행 이름이 남아 채점 때 "어떤 진찰을 했는지"의 근거가 됨 | 1 | "양손을 앞으로 뻗게 해 떨림을 보겠습니다" → 자세성 떨림(-/-) |
| 진찰표에 없는 실제 진찰 (unlisted) | 모델이 시작 정보·진찰표(결과 포함)를 보고 같은 형식의 소견을 지어 답함. 기본은 정상 소견, 새 이상 소견은 만들지 않음. 증례·진찰별로 저장해 어느 팀이든 같은 답 | 1 | "무릎 반사를 보겠습니다" → 슬개건 반사 2+/2+, 대칭 |
| 뭉뚱그리거나 특정 불가 (too\_broad) | 422 EXAM\_NOT\_SPECIFIC. 꽤 구체적으로 보여도 진찰 방법이 여러 가지면 거절(자세성 떨림인지 안정시 떨림인지) | 1 | "신체검진 다 해 주세요" · "손 떨림 확인하겠습니다" → EXAM\_NOT\_SPECIFIC |
| 신체진찰이 아님 (not\_exam) | 422 EXAM\_NOT\_RECOGNIZED. 문진·혈액·영상 검사·처치·기록 작성 등. 진찰이냐 아니냐는 증례와 무관하므로 이 거절로는 진찰표 내용을 알 수 없음 | 1 | "수면 일지를 작성하겠습니다" → EXAM\_NOT\_RECOGNIZED |
| 판정 모델 형식 오류 | 503 EXAMINER\_RESPONSE\_INVALID. 서버 쪽 실패 | 0 | 참가자 코드가 받아서 다시 시도 |
잘못 보낸 진찰 요청도 1턴을 씁니다. 거절 응답에도 turn·turns_remaining이 붙고, 같은 request_id로 다시 보내면 같은 거절이 돌아오며 턴을 또 쓰지는 않습니다. 진찰표에 없는 진찰에도 소견을 지어 답하는 이유: 늘 "특이 소견 없음"이라고 답하면 어떤 진찰이 표에 있는지 추론할 수 있기 때문입니다.

# 턴 계산 예시: 대회 서버, 공개 샘플 C01
| 순서 | 행동 | 보낸 내용 | 결과 | HTTP | 사용한 턴 |
| --- | --- | --- | --- | --- | --- |
| 1 | SAY | 언제부터 잠을 못 주무셨나요? | 한 7년 전부터요. | 200 | 1 |
| 2 | SAY | 증상을 전부 말씀해 주세요 | 한 번에 하나씩 물어봐 주세요. (뭉뚱그린 질문) | 200 | 2 |
| 3 | EXAM | 손 떨림 확인하겠습니다 | EXAM\_NOT\_SPECIFIC | 422 | 3 |
| 4 | EXAM | 양손을 앞으로 뻗게 해 떨림을 보겠습니다 | 자세성 떨림(-/-) | 200 | 4 |
| 5 | EXAM | 무릎 반사를 보겠습니다 | 슬개건 반사 2+/2+, 대칭 (진찰표에 없음 → 소견 작성) | 200 | 5 |
| 6 | EXAM | 신체검진 다 해 주세요 | EXAM\_NOT\_SPECIFIC | 422 | 6 |
| 7 | EXAM | 수면 일지를 작성하겠습니다 | EXAM\_NOT\_RECOGNIZED | 422 | 7 |
| 8 | SAY | 가가가가가… (31자, SDK를 거치지 않고 직접 전송) | CONTENT\_TOO\_LONG | 400 | 8 |
| 9 | DIAGNOSE | 주진단 "수면제 의존" + 기록 | completed | 200 | 8 |
잘못 보낸 요청(422 진찰 거절, 400 30자 초과)도 턴 숫자가 1씩 늘고, DIAGNOSE에서는 늘지 않습니다. 서버 쪽 모델 실패(503)였다면 늘지 않습니다.
SDK를 쓰면 30자 초과는 서버로 보내기 전에 ValueError로 막혀 턴을 쓰지 않습니다. 8번은 SDK를 거치지 않고 HTTP로 직접 보낸 경우입니다.

# 진료가 끝난 뒤: 판정과 채점
| 실행 종류 | 통과·실패 판정 | 채점 | 점수를 보는 사람 |
| --- | --- | --- | --- |
| 개발 키 샘플 진료 (sample.py) | 없음 | 안 함 | — |
| 샘플 검증 (제출 ZIP, 공개 샘플 3건) | 모든 증례가 끝까지 돌고 기록을 냈고, 예선이면 Doctor 모델을 1번 이상 불렀는가 | 가상 환자·진찰 판정·채점 모두 gpt-6-luna (low·low·medium). 채점 실패 시 1번 더 시도. 점수가 없어도 통과·실패는 그대로 | 우리 팀만 (참고 점수) |
| 공식 평가 (리더보드 5증례) | Doctor 모델 미호출 증례는 0점 | 임상 채점·진단 판정 gpt-6.1-sol high, 친절도 gpt-6.1-sol low → 6개 영역 100점 → 증례 평균 | 리더보드는 총점, 영역별 점수는 우리 팀만 |
| 예선 최종 평가 (10증례) | 같음 | GPT · Claude · Gemini 세 모델 채점의 평균 | 최종 순위 |
채점 모델이 받는 것
서버에 기록된 대화·진찰 기록, 제출한 기록 텍스트, 비공개 루브릭(문진·진찰·검사·설명·안전 항목). 참가자의 Doctor 프롬프트는 받지 않음
질문하지 않고 기록에만 적은 내용은 "수행"으로 인정하지 않음 — 판정 근거는 기록 문장을 글자 그대로 인용해야 함

# 참가자 로컬(개발 키) 실행과 서버 실행의 차이
| 항목 | 개발 키트 (완전 로컬, develop.py) | 개발 키 + sample.py | 서버 실행 (샘플 검증·공식 평가) |
| --- | --- | --- | --- |
| 코드가 도는 곳 | 참가자 컴퓨터 |  | 우리 서버의 격리 컨테이너, 증례마다 새로 |
| 인터넷 | 됨 (아무 API·다운로드 가능) |  | 안 됨. 대회 API만. 실행 중 모델·데이터 다운로드는 실패 |

# 참가자가 자주 겪을 차이 세 가지
서버에 내기 전에 코드를 돌려 보는 방법은 두 가지
develop.py — 서버 없이 내 컴퓨터에서 전부 흉내 냄. 가상 환자도 참가자가 고른 모델
개발 키트
코드는 내 컴퓨터에서 돌고, 가상 환자·진찰 판정·Doctor 모델은 우리 서버 것을 씀
개발 키 + sample.py

① 로컬은 되는데 서버는 실패
② 로그는 일부만 보임
③ session() 응답 차이
실행 중 인터넷 다운로드
홈 폴더에 캐시 쓰기 (Hugging Face 등)
requirements.txt에 없는 패키지
8GB를 넘는 메모리
→ 모두 서버에서 실패
서버에서 실패하면 샘플 검증은 증례별 사유와 stderr 끝 30줄만, 리더보드 평가는 사유만 보임
개발 키트와 시작 패키지의 local.Dockerfile(인터넷 없이 읽기 전용으로 실행)로 먼저 확인해야 함
개발 키 샘플에서는 지난 행동 기록(events)이 함께 오지만 서버 실행에서는 오지 않음
대화 기록은 참가자 코드가 직접 들고 있어야 함 (기본 에이전트처럼)

# 한 턴의 흐름 (기본 에이전트)
① Doctor에 "다음 행동" 질문
client.chat(reasoning_effort=medium)
② 답(JSON) 검사
30자·형식 확인 후 SAY / EXAM 전송
③ 서버가 모델 호출
가상 환자 또는 진찰 판정
④ 결과를 진료 기록에 붙임
다음 턴의 사용자 메시지로

Doctor 프롬프트 (기본 에이전트)
재시도 규칙
시스템: 외래 진료실 의사 역할. 매번 JSON 하나만 출력 — {"action":"SAY","content":"…"}(30자 이내) · {"action":"EXAM","content":"진찰 동작 하나"} · {"action":"DONE"}
진행 순서: 주호소 → 현병력 → 과거력·약·알레르기 → 가족력 → 사회력 → 계통 문진 → 관련 신체 진찰 → 진단·계획 설명 → DONE. 질문은 한 번에 하나, 이미 물은 것은 다시 묻지 않음
사용자 메시지: 매 턴 새로 생성 — 시작 정보 + 진료 기록(대화가 한 줄씩 쌓임) + 남은 턴. 남은 턴 ≤10이면 "문진을 마무리하고 EXAM", ≤2이면 "진단과 계획을 쉬운 말로 설명(SAY)" 지시가 덧붙음
서버가 엘리스로 보낸 설정: max_completion_tokens 2048, stream, reasoning_effort medium. temperature는 보내지 않아 모델 기본값
빈 답(503 PROVIDER_RESPONSE_INVALID): 2초·5초·10초 기다렸다가 같은 내용으로 다시 물음(with_retry)
30자 초과·형식 오류: 답을 버리고 "직전 출력은 형식에 맞지 않았습니다. 30자 이내의 JSON 하나만 출력하세요."를 붙여 바로 다시 물음(next_step, 최대 3번)
진찰 거절(422): 답 없이 1턴이 줄고, "(알림: 오류 코드, 1턴 사용. …)"을 진료 기록에 붙여 다음 행동을 고를 때 참고하게 함
턴 소진(MAX_TURNS = 30, 대회 한도는 50): 진료를 멈추고 write_record()로 초진 기록 작성 → client.diagnose()
