# Tinnitus 빈 출력의 순차 진단 결과

2026-10-13 KST에 Tinnitus 문서 하나로 새 모델 호출 10회를 수행했다. **기존 입력은 두 번 모두 빈 결과였고, 어휘와 추출 지침을 결합한 T7은 두 기준 관계를 두 번 모두 복원했다. 그러나 같은 지침의 음성 대조에서 감별 목록을 질환–증상 관계로 잘못 추출했다. 따라서 T7의 추출 개선은 재현되었지만 안전한 해결책으로 채택할 수 없다.**

## 조건별 결과

T2–T6은 T1에서 각각 하나의 요소만 변경했다. T7에서만 이 변경을 결합했다. 음성 대조를 제외한 모든 실제 호출은 동일한 전체 원문 1–84줄을 사용했다.

**T8의 15–23줄 발췌는 실행하지 않았다.** T7이 양성 기준을 처음 충족하면 기준 재호출·조건 재호출·음성 대조로 종료한다는 선택된 분기를 따랐다. T8 및 사용하지 않은 음성 대조 입력은 준비만 했으며 호출 기록과 구분된다.

## 무엇이 확인되었는가

**어휘를 작업 입력에 명시하는 방식은 기여 요인이라는 예비 근거가 있다.** T2에서 Hypertension 관계 하나가 복원되었다. 다만 T2는 한 번만 호출했고 두 번째 관계는 누락했으므로, 어휘 명시만으로 해결된다고 판단하지 않는다. 출력 스키마는 모든 호출에서 동일했다. 작업 프롬프트에 어휘가 없다는 사실은 제공자 측 모델 입력에도 어휘가 없었다는 뜻이 아니다.

**개별 문구의 독립적인 효과보다 결합 효과가 관찰되었다.** T3–T6의 단독 변경은 모두 빈 결과였다. T7은 두 번 모두 두 관계를 복원했고, 사이에 반복한 기준 입력은 다시 빈 결과였다. 이 관측은 승인 어휘의 명시와 추출 의미 설명의 상호작용을 지지하지만, 어떤 지침이 필수였는지는 구분하지 못한다. 관측한 결과에 반복성은 있으나 소수 호출만으로 통계적인 인과 확실성을 주장하지 않는다.

**적극적인 추출과 관계 성립 조건의 구분이 함께 필요하다.** 음성 대조에서 모델은 Meningitis → Tinnitus Pattern을 만들고 67–73줄을 정확히 인용했다. 그 인용은 “Differential diagnosis for tinnitus includes”와 질환 목록이다. 현행 계약은 감별 목록만으로 관계를 만들 수 없다고 명시하며 T7에서도 이 금지 문구는 유지되었다. 모델은 문구가 유지되어도 그 경계를 지키지 못했다. 검증기가 정확한 인용을 확인했다는 사실은 해당 인용이 주장한 관계를 지지한다는 뜻이 아니다.

음성 대조 원응답은 그대로 보존하고 **전체 응답을 의미 검토에서 거부했다.** Meningitis 후보만 삭제하거나 빈 결과로 교체하지 않았다. 음성 대조 결과와 전체 의미 품질 게이트는 `fail`이다.

## 가설의 현재 상태

| 가설 | 현재 판단 |
| --- | --- |
| H1: 승인 어휘를 작업 입력에 명시하지 않아 선택이 불확실하다 | 부분 지지. T2에서 한 관계가 복원되었지만 단독 해결이나 반복성은 미확인 |
| H2: 생략 중심 지침이 과도한 제외를 유도한다 | 단독 변경은 개선하지 못함. 조합에서 추출이 증가했으나 감별 목록 오추출도 발생 |
| H3: 제목의 주제만 추출한다 | 단독 범위 명시는 개선하지 못함. 독립적인 원인으로 확정할 근거 없음 |
| H4: 추가 속성이나 완전한 양상이 필요하다고 해석한다 | 단독 설명은 개선하지 못함. T2·T7에서 실제 0-Feature Pattern 생성 가능성을 확인 |
| H5: 같은 문장의 미승인 개념 때문에 전체를 제외한다 | 단독 설명은 개선하지 못함. T2에서 같은 문장의 Hypertension만 정확히 추출할 수 있었음 |
| H6: 문서에 승인 어휘 관계가 없다 | Tinnitus의 두 기준 관계를 설명하는 원인으로 배제 |
| H7: 긴 입력이나 작업 복잡도가 문제다 | T8 미실행. 전체 문서의 T7 성공으로 전체 원문에서 추출 자체가 불가능하다는 주장은 배제하지만 길이의 영향은 미검증 |

후처리 삭제·원문 누락·표현 불가능한 스키마·미승인 기준 용어·관측된 인증 실패나 시간 초과는 이번 누락을 설명하지 않는다. 반면 모델 내부의 생략 이유와 제공자에 전달된 전체 요청은 관측하지 못했다.

이번 조사로 좁혀진 범위는 **동일한 스키마 안에서도 작업 입력이 승인 어휘 선택과 관계 성립 판단을 충분히 유도하지 못하는 문제**다. 기준 입력에서는 과도한 생략이, 결합 입력에서는 감별 목록의 과도한 관계화가 관찰되었다. 이는 결과를 설명하는 해석이며 단일 내부 원인의 확정이 아니다.

## 후속 제안과 수용 경계

우선 제안은 **명시적 승인 어휘를 유지하면서 직접적인 원인·연관 진술과 감별 목록을 구분하는 좁은 지침을 검증하는 것**이다. 일반적인 추출 의무를 더 강화하는 방식은 이번 음성 대조 때문에 우선하지 않는다. 같은 Tinnitus의 양성·음성 원문을 함께 유지하고, 실제 정답 관계를 모델 입력에 넣지 않은 채 최소 지침의 효과를 확인해야 한다. 결합 조건에서 한 지침씩 제거하는 실험은 이후에 필요한 요소를 좁히는 방법이다. 이러한 후속 호출은 선택하거나 실행하지 않았다.

공용 프롬프트와 스키마는 변경하지 않았다. 기존 2문서·10문서 파일럿, 승인 영수증·어휘·기초 Turtle·submission 파일을 포함한 보호 대상 118개 파일의 해시를 확인했다. 앞선 파일럿의 원래 manifest를 사용하여 2문서 파일럿 18개·10문서 파일럿 70개 파일도 전체 검증했다. 이번 실험의 후보는 임상 지식이나 제출 지식으로 수용하지 않았다. 기존 파일럿의 품질 실패도 성공 결과로 덮어쓰지 않는다.

모든 10회에서 CLI 종료·완료 이벤트·원응답 보존·엄격한 Pydantic·문서 해시 검증은 통과했다. 인용을 출력한 4회에 포함된 6개 span은 허용 줄 범위와 정확한 원문 인용 검증을 통과했다. 나머지 빈 출력 6회에는 검증할 span이 없었다. 모델 도구 이벤트 0개와 기록된 모델 프로세스 종료를 확인했다. 최종 검증은 `verification.json`, 의미 판단은 각 호출의 `review.json`을 참조한다.

임상 전문가 검토, 공용 프롬프트 채택, RDF 생성·수용, submission 수용은 모두 `not_run`이다. 단일 문서의 두 기준 관계와 음성 발췌 외의 문헌·전체 관계에 대한 정확도나 재현율은 추정하지 않는다.

준비 스크립트의 최초 실행에서 import 경로 오류가 발생했으며 프로젝트 루트를 Python 탐색 경로에 추가한 뒤 수정했다. 이 준비 오류에서는 모델 호출이 없었고, 실제 모델 호출의 재시도도 없었다.
